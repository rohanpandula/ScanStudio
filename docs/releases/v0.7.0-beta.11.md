# ScanStudio v0.7.0-beta.11

beta.10 fixed the bug that stopped the first live Windows validation at its
last click; this release fixes everything else that validation surfaced. Every
change below traces to a numbered finding from that session on real hardware
-- a Windows 10 machine, WSL2, usbipd-win, and a Nikon LS-5000 -- and the one
Windows-lane item deliberately not addressed here is named at the bottom.

## Everything that changed

### The real scanner no longer requires an app restart to appear

- Device discovery attempted the bridge exactly once, at engine startup. On
  Windows the bridge stack often becomes healthy moments later, and the real
  scanner then stayed invisible until a full app restart. The engine gains a
  rescan request -- one deliberate re-attempt of the real-backend startup,
  idempotent, degrading to the simulator-only list exactly like startup does,
  and refused while any device is connected so an active session's backend
  can never be replaced underneath it -- and the device panel gains a Rescan
  button, disabled while connected or busy.

### Windows finally has an engine log file

- A Start-menu launch discards the app's console output, so every engine
  diagnostic was simply lost; the live validation's failures had to be
  reconstructed from screenshots. Engine diagnostics now also append to a
  bounded log file under the platform's application-log directory (one
  megabyte, one rotation, about two megabytes worst case), and logging can
  never break the engine event loop -- any logging failure degrades to the
  old console-only behavior.

### The setup checker now proves the deployed bridge is the shipped one

- The live session's sharpest lesson: a stale WSL bridge -- deployed days
  earlier and inherited through a virtual-machine clone -- passed the
  existing bridge presence and startup probes all session, then refused the
  first real capture on the driver's own bundle-identity check. Nothing had
  ever bound the deployed bridge to the installed app. A new bridge-identity
  probe hashes the deployed bridge's two driver-identity files and compares
  them byte-for-byte against the installed payload's corresponding-source
  copies; a mismatch is a red row whose fix text is the one-line redeploy.
  The Windows lane runbook documents the row, and the repository's
  runbook-consistency test enforces that documentation.

### An empty transport now refuses a preview instead of silently doing nothing

- A preview requested with no film loaded spent minutes in motion-adjacent
  work and then completed with zero frames and no explanation anywhere in
  the interface. The engine now probes a fresh scanner status -- the same
  live path the status display uses, never a cached snapshot, so a
  just-fed roll can never be falsely refused -- and refuses the preview
  typed, before any motion, when film is definitively absent. A transport
  that cannot report presence still proceeds, because a preview is exactly
  how presence becomes known there. The refusal renders in the existing
  failure surfaces with operator guidance.

### The hardware-session launcher explains the relaunch race

- Relaunching the hardware session within a few seconds of closing the app
  made the fresh instance exit immediately (the previous instance's browser
  runtime is still shutting down), and the launcher console then showed a
  fully armed-and-disarmed session with no hint anything was wrong. The
  launcher now names that likely cause whenever the app exits within ten
  seconds of starting.

## Validation

- The empty-transport refusal is covered by an end-to-end test that runs
  the exact live scenario against the mock bridge and proves, via the
  bridge call log, that the refusal happens before any motion-capable
  call; the test is mutation-proven (disabling the gate makes it fail with
  the motion call reaching the bridge).
- New unit coverage: rescan's three contract cases, the bridge-identity
  probe's four outcome classes against a fake command executor, log-file
  rotation at the size cap, and the device panel's rescan flow including
  its disabled-while-connected state.
- Full suites on the release commit: the engine's twenty-five test suites
  green in both vendored copies, the desktop shell crate green, the
  frontend green, and all continuous-integration jobs including the
  vendor-mirror gate (engine-pair fingerprint re-pinned for the reviewed
  two-sided edits) and the CoolScanPy PyPI byte-comparison gate.
- Both the designs and the diff passed independent adversarial review
  before merge.

## Platform support and installation

- **macOS Apple Silicon -- Beta:** the Nikon LS-5000 real-film workflow
  remains the validated hardware path. Download
  `ScanStudio-0.7.0-beta.11-macOS-arm64.dmg`.
- **macOS Intel -- Preview:** built and package-tested natively in CI; real
  scanner validation is still pending. Download
  `ScanStudio-0.7.0-beta.11-macOS-x86_64.dmg`.
- **Windows x64 -- Preview:** use the setup executable on a clean system. The
  portable zip requires Microsoft Edge WebView2 to be installed already.
  Scanner access requires WSL2, Ubuntu 24.04, and usbipd-win.
- **Linux x64 -- Preview:** choose the AppImage or portable tarball. The host
  must provide compatible SANE/libusb runtime packages for discovery and
  scanning; the eject path does not use SANE.

The bundled CoolScanPy driver remains 0.7.2, identical to the sdist
published on PyPI; the release gate byte-verifies that equality.

All macOS builds in this release are ad-hoc signed and unnotarized. The
Windows installer and Linux packages are unsigned. Download from the GitHub
Releases page, verify the package against `SHA256SUMS`, and keep the prior
installed app or DMG as a rollback artifact. On macOS, use the normal
Control-click **Open** confirmation if Gatekeeper asks; do not disable
Gatekeeper globally.

## Known limitations

- The remaining Windows-lane parity item is deliberate: the manual frame
  placement affordance the macOS app offers when registration refuses with
  a cropped first frame has no Windows counterpart yet. It is a feature
  port through the motion and binding path and will be built as its own
  change, not rushed into a fix round.
- The full Windows live preview with frame registration established on
  real hardware remains the next validation step; the last live run
  reached the registration gate itself, which correctly refused a roll
  whose first frame sits inside the leader margin at the feeder's fixed
  grab position.
- The attended-binding path has not yet been exercised on a roll that
  genuinely detects at medium confidence. The unattended thresholds are
  unchanged.
- A mounted slide cannot be ejected by command at all; the interface
  specification marks the mount adapter's unload capability absent. The
  driver refuses typed before any motion; the physical remedies remain the
  adapter's manual eject button or power-on auto-eject.
- Motion arming on Linux remains deliberately manual: both the environment
  variable and the non-empty latch file must be set by the operator.
- No Apple Team ID, Developer ID Application identity, secure signing
  timestamp, notarization, or staple is configured yet. Automatic
  installation therefore fails closed by design; this beta must be
  installed manually.
- Intel macOS, Windows, and Linux remain previews pending real-scanner
  end-to-end validation of this release's binaries.
- The separate web/gateway work is not included in these desktop release
  packages.
