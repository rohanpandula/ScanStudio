# ScanStudio v0.7.0-beta.18

This beta adds CLI calibration, repeat capture, and automation. It is being
released for external testing before the remaining attended hardware checks.
Software checks passed; repeat-capture hardware acceptance, preview-derived
exposure acceptance, and calibration quality remain unverified.

## Everything that changed

- Save a roll without scanning, solve and retain a measured RGB exposure lock,
  capture labeled repeated passes, verify receipt-bound artifacts, and collect
  immutable calibration copies through the CLI.
- Held scanner status uses the existing USB reservation. Each held capture
  round has distinct journal and acknowledgement paths; repeated CLI passes
  wait for idle and track their exact admitted jobs. Exposure evidence binds
  to the capture timestamp instead of guessing from the newest journal.
- Add retained-image render/export, metadata on private copies, HTML reports,
  declarative jobs, diagnostics and evidence ZIPs. Existing output destinations
  provide per-frame delivery; archive, positive and preview routes remain
  project-contained, while raw exports can use external destinations.
- Add numbered hopper runs, bounded waits and hooks, observer recovery,
  controller labels, host-scoped idempotency and a managed headless LaunchAgent.
  All scanner workflows remain available through the CLI.
- Experimental `roll run --preview-derived-exposure` meters one preview
  reference and applies positive-only RGB adjustments capped at 1 EV and
  device limits. IR remains metered. Missing or ambiguous preview evidence
  and incompatible capture geometry refuse the operation. This option is
  **off by default** and has not completed attended hardware acceptance.
- Reuse the driver's existing observed-boundary registration. Remove a
  redundant correction that would shift already registered frames twice.
- Fix collection of the production infrared TIFF marker and preflight path
  handling for macOS symlink aliases such as `/tmp` and `/private/tmp`.
- Bundle CoolscanPy 0.7.10 with the held-session fixes also published for
  standalone driver users.

## Validation

The integrated candidate passed all eight CI gates: app/engine, bridge,
CoolscanPy, package build, macOS 14 package check, updater integration,
supply-chain checks and the required verification gate. Local constituent
coverage included 706 Rust tests with two existing evidence-dependent tests
ignored, 920 Swift tests plus focused follow-up checks, and 229 related driver
tests. The signed CLI11 candidate passed packaging, relocation, strict deep
signature verification and all three isolated CLI selftests: stalled capture,
feed-jam recovery and observer reattachment.

Earlier LS-5000 ED/SA-30 evidence includes one completed frame 2 capture at
4000 dpi, 16-bit RGBI and 1x sampling. Its capture bytes and bound artifact
hashes verified, but the measured clipping warning means it did not pass the
no-clipping check. A second held round refused stale journal identity; the
subsequent per-round path fix has passed software tests but has not yet passed
an attended two-pass hardware run. The corrected collection command copied
that retained capture with matching RGB, IR and meter hashes.

The final local hardware attempt reported no film and timed out waiting for
film detection without sending a preview or scan. Simulator success is not
claimed as evidence for physical focus, transport, exposure or calibration.
The simulator correctly refuses preview-derived exposure when measured
preview evidence is unavailable.

## Platform support and installation

Apple Silicon Macs running macOS 14 (Sonoma) or newer are supported. Download
`ScanStudio-0.7.0-beta.18-macOS-arm64.dmg` from this prerelease. The release
workflow signs, notarizes and staples the app and DMG before publication.
Intel Macs, Windows and Linux are not supported ScanStudio platforms.

Read [the CLI guide](../CLI.md) and [hardware support matrix](../HARDWARE-SUPPORT.md).
The bundled CLI is `ScanStudio.app/Contents/MacOS/scanstudio-cli`. Start with
`doctor`, `status` and `diagnostics export`; use the documented film and motion
confirmation flags for attended scanning. External testers should use expendable
film, preserve original captures and include diagnostics with failure reports.

## Known limitations

This release explicitly defers the remaining attended hardware checks to
external testers. The LS-5000 ED is the only verified model, with evidence
limited to the recorded scanner and adapter configurations. Other recognized
scanners, including LS-50, require the existing unverified-hardware opt-in and
have not been physically validated during this milestone.

Repeated held capture, a full preview-derived exposure roll, and the physical
calibration campaign remain unverified. Preview-derived exposure stays off
by default; it does not establish clipping or color accuracy. Four-sample
capture remains the production default, while the existing single-frame
qualification enables 1x capture. Stop after a failed motion and inspect its
receipt and diagnostics rather than blindly retrying. No original receipt,
journal or capture is rewritten to make these checks pass.
