# ScanStudio v0.7.0-beta.9

This release closes the loop that beta.8's live validation opened. Every fix in
it traces to something a real LS-5000 demonstrated within the last day: two
eject-reporting defects the hardware exposed on beta.8's release day, the
retirement of SANE from the eject path after the vendor eject was caught
accepting a command it never executed, an attended path for the rolls that
preview fine but refused to scan, and the first Windows and Linux binaries that
carry the correct application icon and a consistent license snapshot.

The bundled CoolScanPy driver moves to 0.7.2, published to PyPI in lockstep and
byte-verified by the release gate.

## Everything that changed

### Eject, correct end to end

- A roll eject from a deep transport position is a full mechanical rewind that
  outlived the engine's generic bridge-call deadline: the engine declared the
  bridge unhealthy and reported a session loss while the eject completed
  physically. Ejects now run under their own deadline, sized to dominate the
  bridge's bounded worst case with margin, and a genuine expiry names the true
  state -- film position unknown, not failed -- while preserving the quarantine
  semantics for real transport death. Regression tests were proven against a
  deliberately broken wiring before merge.
- The bridge's vendor-eject confirmation probed for film presence immediately
  after the eject call returned -- during the scanner's post-motion attention
  drain -- and reported a false failure on a physically successful eject. The
  confirmation now settles across the drain with a bounded retry window, sized
  against the driver's own inner settle loop, tunable by environment variable.
  A definitive still-present verdict remains an immediate parked refusal.
- The driver no longer ejects through SANE at all. CoolScanPy 0.7.2 replays the
  scanner's own traced Unload sequence over its own USB transport, gates on the
  interface specification's per-adapter capability bit so unsupported adapters
  (the MA-21 mount) refuse typed before any motion, and confirms completion by
  polling through the becoming-ready drain to a definitive medium-not-present.
  Live today: a full roll ejected clean in 11 seconds with all four command
  statuses good, and the mount adapter refused with zero motion, its capability
  byte matching the specification bit for bit. python-sane and host scanimage
  are no longer part of the eject path on any platform.

### Attended scanning for medium-confidence rolls

- A roll the detector places at medium confidence can now be scanned when the
  operator explicitly approves every requested frame. The attended verdict is
  derived from approval receipts the batch already authenticates -- inside the
  signed binding payload, so there is no wire field to forge -- and the journal
  records the attended origin on every frame. Unattended medium and all
  low-confidence rolls refuse exactly as before.
- The approval wire passes the attended marker only when the operator opted in,
  so ordinary approvals remain compatible with any driver version, and an
  attended approval against a driver too old to support it is refused typed
  rather than surfacing as an internal error.
- Field validation on a roll that genuinely detects at medium is the remaining
  step; the machinery is corpus- and unit-validated end to end.

### Windows packaging correctness

- The Windows resources job now stamps the release version before assembling
  the license snapshot, so the lockfile copies inside the installer agree with
  the version the binary reports. Previously the shipped
  `Licenses/Rust-App-Cargo.lock` said 0.3.0 inside an installer that correctly
  reported its real version everywhere else.
- The Windows and Linux application icon is now the real ScanStudio artwork.
  The Tauri port had shipped the scaffold generator's placeholder icons since
  its first commit; all sixteen icon assets are regenerated from the same
  canonical source as the macOS icon and pixel-verified against it.

### Documentation

- The protocol document's device-info shape now matches the actual struct,
  including the device-advertised multisample capability added in beta.8.

## Validation

- All continuous-integration jobs are green on the release commit, including
  the vendor synchronization gate across all four mirrored pairs and the
  CoolScanPy PyPI gate byte-comparing the bundled driver against the published
  0.7.2 sdist.
- Live hardware, same day, real LS-5000: the spec-based Unload eject validated
  on both adapter classes (SA-30 full-roll physical eject, presence-confirmed
  in 11.25 seconds; MA-21 typed refusal with zero motion). The two
  eject-reporting fixes were built from timing evidence captured on this
  hardware earlier the same day.
- Driver suites: 1796 tests green in the primary bundled copy, 1800 in the
  mirror, including the new unload and attended-binding coverage. Bridge: 365
  and 383. Engine: 643 and 658 across both copies. macOS app: 484 tests in 50
  suites. Tauri frontend: 422 tests with 6 expected skips.
- Every substantive change passed independent adversarial review before merge;
  the eject-deadline regression tests were additionally proven by mutation
  (the tests fail when the fix is deliberately broken).

## Platform support and installation

- **macOS Apple Silicon — Beta:** the Nikon LS-5000 real-film workflow remains
  the validated hardware path. Download
  `ScanStudio-0.7.0-beta.9-macOS-arm64.dmg`.
- **macOS Intel — Preview:** built and package-tested natively in CI; real
  scanner validation is still pending. Download
  `ScanStudio-0.7.0-beta.9-macOS-x86_64.dmg`.
- **Windows x64 — Preview:** use the setup executable on a clean system. The
  portable zip requires Microsoft Edge WebView2 to be installed already.
  Scanner access requires WSL2, Ubuntu 24.04, and usbipd-win.
- **Linux x64 — Preview:** choose the AppImage or portable tarball. The host
  must provide compatible SANE/libusb runtime packages for discovery and
  scanning; the eject path no longer uses SANE or scanimage.

All macOS builds in this release are ad-hoc signed and unnotarized. The Windows
installer and Linux packages are unsigned. Download from the GitHub Releases
page, verify the package against `SHA256SUMS`, and keep the prior installed app
or DMG as a rollback artifact. On macOS, use the normal Control-click **Open**
confirmation if Gatekeeper asks; do not disable Gatekeeper globally.

## Known limitations

- The attended-binding path has not yet been exercised on a roll that
  genuinely detects at medium confidence; today's live rolls detected at high.
  The unattended thresholds themselves are unchanged.
- A mounted slide cannot be ejected by command at all -- the interface
  specification marks the mount adapter's unload capability absent, confirmed
  live. The driver now says so before moving anything; the physical remedies
  remain the adapter's manual eject button or power-on auto-eject.
- Motion arming on Linux remains deliberately manual: both the environment
  variable and the non-empty latch file must be set by the operator.
- No Apple Team ID, Developer ID Application identity, secure signing
  timestamp, notarization, or staple is configured yet. Automatic installation
  therefore fails closed by design; this beta must be installed manually.
- Intel macOS, Windows, and Linux remain previews pending real-scanner
  end-to-end validation of this release's binaries.
- The separate web/gateway work is not included in these desktop release
  packages.
