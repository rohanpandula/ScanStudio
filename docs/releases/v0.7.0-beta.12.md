# ScanStudio v0.7.0-beta.12

This release fixes the two defects behind the long-running refeed-error thread
(ScanStudio #16) reported by Alberto and two other operators: a roll preview
whose physical frame gaps are present but partially occluded -- the signature
of a full-roll-modified SA-21 strip feeder -- was refused outright with
REFEED_REQUIRED on every attempt, and the manual-placement fallback that
should have rescued exactly those captures crashed with an INTERNAL journal
error before it could render anything.

## Everything that changed

### Occluded-gap rolls now bind at medium confidence instead of refusing

- The field reports all carried the same shape: the detector found and
  anchored the same frame lattice it finds on stock adapters -- it passed
  every structural floor, including at least three cleanly detected gap runs
  agreeing on pitch and phase -- but the clean-gap fraction fell below the
  medium gate because intruding mask edges dim the inter-frame rows below the
  strict clear-film bar. The detection was labeled "low", which refuses the
  preview; worse, the scan gate admits nothing below "high" even when a human
  approves every frame through the attended binding path, so there was no way
  forward at all.
- An anchored comb with an unambiguous lattice margin (the same 0.08 bar the
  high gate already requires) and at least three independently supported
  boundaries now binds at medium with a `degraded-gap-evidence` warning.
  Every weak slot stays flagged for manual review, unattended fine scanning
  still requires high confidence, and heavily degraded captures whose
  boundary evidence averages under the medium score bar keep the honest
  refusal they had before. The tier is additive: healthy rolls are unchanged
  bit-for-bit.
- Field reports now also carry `lattice_margin` and `direct_fraction`, so the
  next report of this class names which gate tripped instead of forcing a
  blind replay.

### Manual placement works again after a refused preview

- When a preview was refused, the UI's fallback -- draw boundaries by hand on
  the captured strip (`roll.previewStrip` / `roll.manualFrames`) -- failed
  with INTERNAL: "preview journal status='complete', expected
  'awaiting-hold-job'". The reconstructed attempt is validated from disk, and
  every refused preview's journal is the terminal preview-and-hold shape:
  the hold decision tears the reservation down, flipping status to complete
  and unit_released to true while capture_mode stays preview-and-hold. The
  validator only accepted the paused-at-hold-boundary shape, so the escape
  hatch crashed on precisely the field reports it existed for.
- Both terminal hold outcomes (released and ejected) now validate; a hold
  resumed into a fine scan still fails closed, as does any inconsistent
  journal.

### Driver release discipline

- The driver changes ship in CoolScanPy 0.7.3, published to PyPI from the
  upstream repository before this app release is tagged, so a standalone
  `pip install coolscanpy` user and an app user run byte-comparable code for
  the same film (owner policy). The release gate authenticates the exact
  0.7.3 sdist against pins updated in this change, and the vendored tree's
  deliberate divergences are re-pinned on both sides.

### Windows supply-chain re-pin

- Microsoft rotated the fwlink 2124701 WebView2 delivery GUID again between
  releases (third rotation). Tauri's bundler resolved the new GUID during a
  package build, ignored the pinned copy staged under the old path, downloaded
  a fresh installer into its own cache directory, and the pinned-tool verifier
  failed closed on the unexpected directory -- the lockdown catching real
  upstream drift exactly as designed. Both pin sites move to the new GUID with
  the replacement artifact re-verified via the official redirect first.

## Validation

- An offline reproduction built from the field numbers (lattice score about
  0.48 against the reports' 0.4622-0.4653, margin well above the high bar,
  four directly supported gaps) scores low before the change and medium after
  it; healthy rolls stay high with no new warning, and a heavier-degradation
  variant that falls under the medium score bar still refuses.
- New regression coverage: the occluded-gap tier (admission, healthy-unchanged,
  stays-low guard), all three valid held-journal shapes plus refused outcomes
  (resumed-as-batch, missing outcome), and the bridge transport rendering a
  strip and arming manual placement from released/ejected hold attempts.
- Full suites green on the release commit in canonical and vendored copies:
  CoolScanPy, bridge, engine, desktop shell, frontend, and every
  continuous-integration job including the vendor-mirror gate and the PyPI
  byte-comparison gate against the published 0.7.3 sdist.
- Full disclosure (record corrected per #104): at tag time, two Verify runs
  for the exact tagged commit failed on ONE stale test literal -- the
  source-tree version-fallback assertion still expected 0.7.2 after project
  metadata moved to 0.7.3 -- while this Release workflow succeeded and an
  earlier draft of these notes claimed every CI job was green. The failing
  assertion was stale and the shipped fallback returned the correct version,
  so there is no runtime defect in these packages; but publication should
  have been blocked until the verification set agreed, and the gate now
  requires exactly that for every future release.
- The Windows package job went red mid-round on the GUID rotation above and
  was proven green again end-to-end on the re-pinned artifact before merge;
  both designs passed adversarial review before landing.

## Platform support and installation

- **macOS Apple Silicon -- Beta:** the Nikon LS-5000 real-film workflow
  remains the validated hardware path. Download
  `ScanStudio-0.7.0-beta.12-macOS-arm64.dmg`.
- **macOS Intel -- Preview:** built and package-tested natively in CI; real
  scanner validation is still pending. Download
  `ScanStudio-0.7.0-beta.12-macOS-x86_64.dmg`.
- **Windows x64 -- Preview:** use the setup executable on a clean system. The
  portable zip requires Microsoft Edge WebView2 to be installed already.
  Scanner access requires WSL2, Ubuntu 24.04, and usbipd-win.
- **Linux x64 -- Preview:** choose the AppImage or portable tarball. The host
  must provide compatible SANE/libusb runtime packages for discovery and
  scanning; the eject path does not use SANE.

The bundled CoolScanPy driver is 0.7.3, identical to the sdist published on
PyPI; the release gate byte-verifies that equality.

macOS builds are Developer ID signed, notarized, and stapled by the release
pipeline. The Windows installer and Linux packages remain unsigned. Download
from the GitHub Releases page, verify the package against `SHA256SUMS`, and
keep the prior installed app or DMG as a rollback artifact.

## Known limitations

- The degraded-gap tier has not yet been exercised live on Alberto's actual
  modified SA-21 hardware; the admission profile was reproduced offline from
  his reports' own measurements, and his next preview attempt is the live
  confirmation. His eject-wedge-after-refusal symptom remains tracked
  separately from this round.
- Attended binding has been exercised on synthetic medium-confidence rolls
  only; a genuine live medium-confidence scan on real hardware remains the
  next validation step. Unattended thresholds are unchanged.
- A mounted slide cannot be ejected by command at all; the interface
  specification marks the mount adapter's unload capability absent. The
  driver refuses typed before any motion; the physical remedies remain the
  adapter's manual eject button or power-on auto-eject.
- Motion arming on Linux remains deliberately manual: both the environment
  variable and the non-empty latch file must be set by the operator.
- Firewire Coolscans (LS-4000 and friends) remain out of scope for this
  USB-only application; discussion continues in #28.
- The separate web/gateway work is not included in these desktop release
  packages.
