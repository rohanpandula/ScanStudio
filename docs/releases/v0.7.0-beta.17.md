# ScanStudio v0.7.0-beta.17

This release adds an agent-operable CLI, shared GUI/headless control, and explicit unverified
scanner policy. Driver publication is complete; attended single-sample
validation passed on the LS-5000 ED/SA-30. The vendored driver is CoolscanPy 0.7.8; its
publication and authenticated artifact pin are recorded below.
[CoolscanPy release PR17](https://github.com/rohanpandula/coolscanpy/pull/17)
merged at `91a01983aee705f23d81c51055b731c1e0b527ab`; the published 0.7.8
source archive is 562282 bytes with SHA-256
`9e19d309468487d480fd4e2b3d2a7a9c9799923bcff75e8615bf99287f43f830`.
The authenticated sync gate preserves exactly eight existing vendored exemptions.

## Everything that changed

- The bundled `scanstudio-cli` controls connection, preview, frame selection,
  settings, roll creation, scan, stop, resume, eject, events, and diagnostics.
  Read [the CLI guide](../CLI.md) for JSON envelopes, exit codes, explicit motion
  confirmations, and the full-roll script.
- CLI frame placement supports absolute row offsets, imported placement documents,
  and replay of saved offsets against the current preview. Busy operations,
  stale previews, and mismatched project media refuse before placement; failed
  replay keeps scan readiness blocked. Exposure solving and the remaining
  calibration workflow are still follow-on work.
- A resident headless host shares the GUI's session construction and policy.
  Socket ownership is claimed before engine creation; concurrent startup
  refuses the losing process. Read-only commands do not start a host.
- Ordered, bounded local transport protects against stale descriptors and slow
  peers. Stop removes only its own socket and PID file. Bundled CLI startup uses
  the existing signed launcher and hardware arming policy; simulator mode is
  isolated from that policy and from the live scanner.
- Packaged acceptance now drives the bundled CLI through an isolated simulator
  roll, including stop/resume and preserved completed receipts. The documented
  full-roll script collects copied evidence and diagnostics without rewriting
  capture records.
- Phase 5 adds a per-command `--allow-unverified-hardware` opt-in and the GUI's
  **Allow unverified scanners** setting. Recognized USB models remain unverified;
  allowing them never relaxes motion, attendance, recipe, or recovery gates.
  CoolscanPy 0.7.8 binds the exact selected USB identity and opt-in through
  capture and held-session resume. No fallback call or ambient opt-in is used.
- Model and verification provenance accompanies status, new receipts, derivative
  TIFF metadata, and diagnostics. Legacy receipts remain readable. No original
  raw image, manifest, receipt, or journal is rewritten to add provenance.
- The production single-sample gate is bound to an attended validation record,
  replacing the old lab environment switch. The recorded CLI run now enables it. CoolscanPy 0.7.8
  covers the IR metering threshold, explicit identity opt-in, and
  sample-count-derived fine-read framing, with the local validation-order correction.

## Platform support and installation

Apple Silicon Macs running macOS 14 (Sonoma) or newer remain the supported
platform. The release workflow requires Developer ID signing, notarization,
and stapling before publishing `ScanStudio-0.7.0-beta.17-macOS-arm64.dmg`.
There is no beta.17 public artifact yet. The bundle includes its bridge runtime,
libusb, corresponding source, and license notices. Intel Macs, Windows, and
Linux are retired ScanStudio platforms.

An LS-50 tester should first read the [hardware support matrix](../HARDWARE-SUPPORT.md).
With the pinned 0.7.8 driver, use:

```sh
scanstudio-cli connect --allow-unverified-hardware
scanstudio-cli status
scanstudio-cli diagnostics export
```

Those commands do not authorize a scan or eject. Obtain explicit per-run
attendance and film confirmations before issuing motion commands. Review
bundles locally before sharing; omit private images, paths, and serial numbers.

## Known limitations

The LS-5000 ED is the only verified model, and its evidence is limited to the
recorded Mac/scanner/adapter configurations. Unverified models use the existing
LS-5000 trace at the operator's risk and may fail during discovery, opening,
focus, metering, preview, or capture. Name-only SANE identities do not imply a
direct-USB capture path. No non-LS-5000 dpi, bit-depth, multisample, or adapter
capability is asserted as validated.

Single-sample (1×) capture is enabled by retained attended evidence
`cli-single-sample-20260908T091904Z` on LS-5000 ED firmware 1.03 / SA-30.
The signed CLI/headless host captured only frame 2 at 4000dpi/16-bit/RGBI/1x:
receipt fingerprint `42ac10bb4c4b88e9`, expected/completed fine bytes 189194240,
RGB `(3946, 5959, 3)` and IR `(3946, 5959)` uint16, one receipt, no transport
recovery, no clipping warning, and a clean transport-smear verdict. Files and
receipt bindings were hash-verified; the rendered preview is coherent, with
native orientation and a magenta cast. This validates single-frame capture,
not color accuracy or a full-roll 1× workflow. Evidence remains in
`~/ScanStudio-QA/cli-single-sample-20260908T091904Z/evidence/capture-verification.json`.
The former environment variable cannot enable the source gate.
The first headless CLI attempt on 2026-09-08 completed preview but refused
the selected 1× frame at a held-session plan check that still expected the
4× READ command (zero fine image bytes, no capture receipt). That failed
attempt is not qualifying hardware evidence. A local driver correction now
binds and validates the canonical plan before applying the sample-specific
READ size; the correction remains within the existing pinned worker exemption.
It passes cold, held-session, continuation, and 1×→4× mock regressions.
Four-sample capture remains the production default. Simulator images cannot
prove real focus, framing, color, infrared repair, or safe film transport.
Blind retries, automatic refeeding, and recovery power-cycles are not authorized.
