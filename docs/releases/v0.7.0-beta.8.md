# ScanStudio v0.7.0-beta.8

This is a field-report-driven fix release. Every headline change traces to an
open issue filed by a tester running real film: the eject-after-failed-preview
trap that ended in a power cycle (#16, #68, #76), scans that finished with
"0 completed" and no reason (#76, #24), a fully built recovery path that was
unreachable exactly when it was needed (#16), and Windows/Linux clients whose
scan requests a real LS-5000 always refused (#24). It also completes the
release-engineering follow-ups from the beta.7 audit, including correct
version stamping: this is the first release whose Windows and Linux binaries
self-report their real version instead of a frozen placeholder.

The bundled CoolScanPy driver is unchanged from beta.7 (0.7.1, byte-identical
to the published PyPI sdist); every fix in this release lives in the bridge,
engine, apps, and packaging around it.

## Everything that changed

### Eject after a failed preview

- A failed roll preview releases the scanner's held reservation as part of its
  fail-closed teardown, which previously left Eject with nothing it was allowed
  to use: it refused before sending any command, the strip stayed inside, and a
  power cycle was the only way out. The bridge now falls back to the
  capability-gated vendor eject when the roll route refuses without having
  attempted anything.
- The vendor eject reports acceptance, not actuation, and this scanner is known
  to accept an eject and never move. Any vendor-route success is therefore
  confirmed through the motion-free film-presence probe before it is reported:
  film still present surfaces as a parked transport, an unconfirmable probe
  fails closed, and only a definite absence counts as ejected.
- Eject failures now reach the client typed end to end. The engine's wire
  vocabulary gained the eject-failed and feeder-parked codes it previously
  flattened to a bare internal error, the service boundary wraps any unmapped
  driver exception with the original type preserved in the message, and every
  eject failure leaves a code-and-message telemetry line.
- On a host without the SANE tools (including the stock macOS bundle) the
  fallback surfaces as a typed error carrying the driver's own
  refeed-and-repreview guidance rather than a generic internal failure.

### Recovery and error surfacing in the macOS app

- Manual frame placement is now reachable from any refeed-required refusal.
  Previously the button only rendered when a diagnosed probable-cause sentence
  existed, which a returned low-confidence detection structurally never gets,
  so the recovery path was invisible in exactly the reported failure. The
  probable-cause sentence still renders whenever a diagnosis exists.
- A scan batch that completes with zero frames now surfaces the driver's
  refusal reason, with honest copy for the unattended-binding confidence gate,
  appended to the batch summary and shown inline in the batch inspector. The
  confidence thresholds themselves are unchanged.
- Error reports and the diagnostic event trail now record the adapter and
  carrier on every applied scanner status, so the next "Adapter: unknown"
  report can distinguish a probe that never ran from one that failed.

### Device-aware multisample on the Windows and Linux clients

- The engine now advertises the connected device's supported multisample
  passes in its device info, sourced from the same bridge-derived set the scan
  gate validates against. The macOS app already decoded this field.
- The Tauri client previously defaulted to a single pass with no device
  awareness, which a real LS-5000 always refuses; every real-hardware scan
  from the Windows and Linux clients failed at the gate. Options and defaults
  now follow the device, are coerced on connect and again immediately before
  every scan request, and the local validator intersects the device's set with
  the protocol invariant instead of replacing it.

### Release engineering, packaging, and docs

- Windows and Linux builds stamp the release version into the Tauri
  configuration, package manifest, and Cargo manifest and lockfile before any
  build step, so the compiled binaries, installer metadata, and installed-apps
  listings report the real version. The macOS bundle's short version string
  moved off its frozen placeholder; the release-stamped identity remains the
  authoritative in-app version.
- The private SANE link-SDK build resolves the bridge interpreter's symlink
  chain instead of rejecting it: a normal virtual environment interpreter is a
  symlink by convention, and the stricter guard introduced during the audit
  refused every real build. A dangling or planted link still fails closed, and
  all interpreter invocations use the resolved path.
- The Windows offline bundle verifier runs its artifact-lock hash check before
  the install-and-import preflight it previously trailed, the NSIS extraction
  helper creates parent directories with a symlink-refusing walk, and its
  device checks read modes from held descriptors instead of re-statting paths.
- The Tauri packaging test suite runs in CI, the pinned-Rust verifier gained
  its first tests, and a helper that pytest mistakenly collected as a test was
  renamed, so the script suites run clean.
- Public runbooks were reworded to describe hardware generically, and the
  protocol document's device-info shape caught up with the actual struct.

## Validation

- All continuous-integration jobs are green on the release commit itself: the
  full Verify workflow and every cross-platform port job ran against the
  merged union of these changes, not only the individual pull requests.
- Native macOS app: 480 tests across 50 suites passed, with each commit in the
  recovery-UI change built and tested in isolation.
- Rust engine: full library and integration suites passed in both the canonical
  and vendored copies, including the new device-info capability tests and an
  end-to-end assertion on the serialized wire key over the real engine binary.
- Python bridge: full suites passed in both copies, with new regressions
  covering the fallback eject's success, failure, parked, busy, and
  unconfirmable shapes, the post-eject close failure, and the end-to-end
  failed-preview-then-eject sequence at both the transport and service layers.
  The new tests were additionally run against the pre-fix sources and fail
  there, confirming they pin behavior.
- Tauri frontend: 419 tests passed with 6 expected skips; the type checker is
  clean.
- Every change in this release passed at least one independent adversarial
  review before merge, and the merged union passed a further adversarial pass
  covering cross-change interactions and the release path, including a dry run
  of the version stamping against the real files and a locked cargo metadata
  check on the stamped result.
- The vendor synchronization gate passes on the merged union with the combined
  divergence fingerprints, and the bundled driver remains byte-identical to
  the published PyPI 0.7.1 sdist.
- The eject fallback's behavior against a physically wedged transport has not
  yet been exercised on real hardware; see the known limitations.

## Platform support and installation

- **macOS Apple Silicon — Beta:** the Nikon LS-5000 real-film workflow remains
  the validated hardware path. Download
  `ScanStudio-0.7.0-beta.8-macOS-arm64.dmg`.
- **macOS Intel — Preview:** built and package-tested natively in CI; real
  scanner validation is still pending. Download
  `ScanStudio-0.7.0-beta.8-macOS-x86_64.dmg`.
- **Windows x64 — Preview:** use the setup executable on a clean system. The
  portable zip requires Microsoft Edge WebView2 to be installed already.
  Scanner access requires WSL2, Ubuntu 24.04, and usbipd-win.
- **Linux x64 — Preview:** choose the AppImage or portable tarball. The host
  must provide compatible SANE/libusb runtime packages, scanner permissions,
  and the normal desktop runtime dependencies. The eject fallback introduced in
  this release shells out to the host's `scanimage`, so install the
  distribution's `sane-utils` package alongside the SANE runtime.

All macOS builds in this release are ad-hoc signed and unnotarized. The Windows
installer and Linux packages are unsigned. Download from the GitHub Releases
page, verify the package against `SHA256SUMS`, and keep the prior installed app
or DMG as a rollback artifact. On macOS, use the normal Control-click **Open**
confirmation if Gatekeeper asks; do not disable Gatekeeper globally.

## Known limitations

- The vendor eject fallback is commanded and presence-confirmed, but its
  efficacy against a genuinely wedged transport has not yet been validated on
  real hardware; the incident record shows a wedged transport can ignore an
  accepted eject, which the presence probe will now report as parked rather
  than as success. A power cycle remains the recovery for a confirmed wedge.
- On macOS the bundled app ships no SANE command-line tools, so the eject
  fallback cannot physically actuate there; it reports a typed error with the
  driver's refeed guidance instead. Physically ejecting after a failed preview
  on macOS still means refeeding or power cycling.
- The unattended-binding confidence thresholds are unchanged: a roll that
  previews below high confidence still refuses unattended scanning, now with
  the reason shown and manual frame placement offered. The detector-threshold
  rework remains a separate, planned change.
- Motion arming on Linux remains deliberately manual: both the environment
  variable and the non-empty latch file must be set by the operator.
- The macOS bundle's short version string reads 0.7.0; the release-stamped
  identity carries the full version and is what the app reports and the
  updater compares.
- No Apple Team ID, Developer ID Application identity, secure signing
  timestamp, notarization, or staple is configured yet. Automatic installation
  therefore fails closed by design; this beta must be installed manually.
- Intel macOS, Windows, and Linux remain previews pending real-scanner
  end-to-end validation of this release's binaries.
- The separate web/gateway work is not included in these desktop release
  packages.
